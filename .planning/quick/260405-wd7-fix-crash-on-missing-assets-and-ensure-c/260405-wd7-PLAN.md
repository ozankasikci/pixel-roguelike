<task type="auto">
  <name>Task 2: Fix Windows CI artifact layout and create macOS CI workflow</name>
  <files>.github/workflows/build-windows.yml, .github/workflows/build-macos.yml</files>
  <action>
1. **Fix `.github/workflows/build-windows.yml` artifact upload:**
   The current `path` list puts `build/apps/runtime/Release/pixel-roguelike.exe` and `assets/` at different directory depths in the artifact zip. The user extracts and gets a nested mess where the exe can't find assets/.

   Replace the upload step's `path` with a pre-packaging step that copies the exe and assets/ into a flat staging directory, then uploads that directory:
   ```yaml
   - name: Package game
     run: |
       mkdir staging
       cp build/apps/runtime/Release/pixel-roguelike.exe staging/
       xcopy /E /I assets staging\assets
     shell: cmd

   - name: Upload game
     uses: actions/upload-artifact@v4
     with:
       name: pixel-roguelike-windows
       path: staging/
       retention-days: 7
   ```
   This ensures the artifact extracts to a flat structure: `pixel-roguelike.exe` + `assets/` as siblings.

2. **Create `.github/workflows/build-macos.yml`:**
   Model it after the Windows workflow but for macOS. Key details:
   - `runs-on: macos-latest`
   - `workflow_dispatch` trigger (same as Windows)
   - Install Homebrew deps: `brew install glfw glm spdlog openal-soft`
   - Setup Python 3.12 and install jinja2 (needed for GLAD code generation)
   - Configure with `cmake --preset ci-macos` (preset already exists in CMakePresets.json)
   - Build: `cmake --build build --config Release --parallel --target pixel-roguelike`
   - Package into staging/ with `cp` and `cp -R assets staging/assets`
   - Upload artifact named `pixel-roguelike-macos` with 7-day retention

   The `ci-macos` preset inherits from `macos` and sets `CMAKE_BUILD_TYPE=Release`. It builds into `build/` with targets `pixel-roguelike` and `level-editor`, but the workflow only needs `pixel-roguelike`.

   Note: On macOS, the built binary path is `build/apps/runtime/pixel-roguelike` (no Release subdirectory since it's a single-config generator, not multi-config like MSVC).
  </action>
