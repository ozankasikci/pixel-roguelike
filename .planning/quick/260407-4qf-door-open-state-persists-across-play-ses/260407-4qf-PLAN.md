<objective>
Fix door open state persisting across play sessions in the level editor.

Purpose: When the user stops play mode, doors (and all other gameplay state) should immediately reset to their baseline state. Currently the reset is deferred until the next play start, so doors opened during play remain visually open after stopping.

Output: Modified editor main loop to call resetForPlay() immediately when play mode stops, then set dirty state to None (reset already done) instead of GameplayStateReset (deferred).
</objective>

  <action>
In the play toggle handler (around line 1941-1945), when play mode is toggled OFF (the `else` branch of `if (ui.playPreview)`), change the behavior from deferring the reset to performing it immediately:

Current code (lines ~1941-1944):
```cpp
} else {
    runtimePreviewSession.endCapture(window.handle());
    runtimePreviewDirtyState = mergeRuntimePreviewDirtyState(runtimePreviewDirtyState,
                                                            RuntimePreviewDirtyState::GameplayStateReset);
}
```

Change to:
```cpp
} else {
    runtimePreviewSession.endCapture(window.handle());
    runtimePreviewSession.resetForPlay();
    // Reset already applied -- no deferred dirty state needed for gameplay.
    // Preserve any pending FullWorldRebuild from scene edits made during play,
    // but clear GameplayStateReset since we just handled it.
    if (runtimePreviewDirtyState == RuntimePreviewDirtyState::GameplayStateReset
        || runtimePreviewDirtyState == RuntimePreviewDirtyState::None) {
        runtimePreviewDirtyState = RuntimePreviewDirtyState::None;
    }
    // If dirty state is FullWorldRebuild or EnvironmentOnly, leave it --
    // those still need processing on next play start.
}
```

This ensures:
- Door state (progress, opening, opened) resets to baseline immediately
- Player position/camera resets immediately
- Checkpoint state resets immediately
- If scene edits happened during play that require a full rebuild, that dirty state is preserved
- The next play start won't redundantly call resetForPlay() when dirty state is None, and will do a full rebuild if scene edits require one
