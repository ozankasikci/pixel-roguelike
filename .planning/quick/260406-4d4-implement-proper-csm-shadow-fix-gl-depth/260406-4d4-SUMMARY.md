# Quick Task 260406-4d4: Proper CSM Shadow Fix — Summary

**Completed:** 2026-04-06
**Commits:** c9721d0, f7755d1, 9977031

## What Changed

Replaced the fragile dual-mechanism CSM shadow bias system (caster-side offset + receiver-side normal offset) with an industry-standard approach that eliminates the root cause of the recurring wall-edge white line artifact.

### Architecture (Before → After)

| Layer | Before | After |
|-------|--------|-------|
| Shadow map construction | Caster offset (0.15 units toward light) — global geometry perturbation | GL_DEPTH_CLAMP — no geometry modification, casters outside frustum clamped |
| Receiver-side bias | Fixed 0.15 world-space normal offset (was dead code until biasedWorldPos fix) | Per-cascade texel-scaled normal offset: `cascadeTexelSize * 2.0 * slopeFactor` |
| Depth bias | constantBias=0.001, normalBias=0.002 | Retained from earlier fix |
| Shadow vertex shader | Had uShadowCasterOffset + uLightDirection uniforms | Simplified to minimal `gl_Position = uLightViewProjection * uModel * vec4(aPosition, 1.0)` |

### Why This Won't Regress

1. **No magic numbers in shadow map pass** — shadow_depth.vert renders true geometry with no offsets
2. **Normal offset auto-scales** — proportional to cascade texel size, not a fixed world-space value
3. **GL_DEPTH_CLAMP is a one-line enable** — impossible to accidentally remove via refactor
4. **No parameter coupling** — each technique is independently correct for its domain

### Known Limitation

Screen-space contact shadows are implemented in scene.frag but **disabled** (`uEnableContactShadows = 0`). The depth pre-pass that feeds them rendered to the wrong FBO, causing massive visual corruption. Contact shadows would provide additional gap-filling for edge cases but are not needed for the current scene. Enabling them requires a proper depth copy implementation.
