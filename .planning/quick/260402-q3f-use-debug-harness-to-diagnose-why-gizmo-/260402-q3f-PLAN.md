Key architectural facts:
- ImGui GLFW backend installed with `ImGui_ImplGlfw_InitForOpenGL(window, true)` — installs its own callbacks
- Input injection approach: Use ImGuiIO API directly (AddKeyEvent, AddMouseButtonEvent, AddMousePosEvent) — NOT GLFW callbacks
- After injecting, call glfwPostEmptyEvent() to wake the event loop from glfwWaitEventsTimeout()
- Debug harness poll() runs on the main thread in the render loop — commands execute synchronously in the same frame
- The editor uses idle event waiting: glfwWaitEventsTimeout(kIdleTimeoutSeconds) when not capturing mouse/keyboard
- EditorPendingCommand tracks gizmo drag state: beginPendingCommand on first hot frame, finalizePendingCommand when no longer hot
- MultiGizmoState caches original transforms during drag and clears when gizmo stops being hot

**Part B: Implement EditorCommander input simulation**

All three use ImGui's IO API for injection, NOT GLFW callbacks. This is correct because ImGui_ImplGlfw_InitForOpenGL was called with `install_callbacks=true`, meaning ImGui's GLFW backend already chains callbacks. But for synthetic input, we bypass GLFW entirely and talk to ImGuiIO directly, which is the supported approach.

After each injection, call `glfwPostEmptyEvent()` to wake the editor's event loop from `glfwWaitEventsTimeout`.

`keyPress(args)`:
- Args: `{"key": "Z", "ctrl": true, "shift": false, "alt": false}` (or `{"key": "W"}` for gizmo mode)
- Map string key names to ImGuiKey values. Support at minimum: W, E, R (gizmo modes), Z, Y (undo/redo), Delete, Backspace, Escape, D, S, P, F, and all letter keys A-Z.
- Implementation:
  ```cpp
  ImGuiIO& io = ImGui::GetIO();
  // Set modifier state
  if (args.value("ctrl", false) || args.value("super", false)) {
      io.AddKeyEvent(ImGuiMod_Ctrl, true);
  }
  if (args.value("shift", false)) {
      io.AddKeyEvent(ImGuiMod_Shift, true);
  }
  // Add key press + release
  io.AddKeyEvent(imguiKey, true);
  io.AddKeyEvent(imguiKey, false);
  // Clear modifiers
  io.AddKeyEvent(ImGuiMod_Ctrl, false);
  io.AddKeyEvent(ImGuiMod_Shift, false);
  glfwPostEmptyEvent();
  ```
- On macOS, Ctrl+Z uses `io.KeySuper` (Cmd key). The args should accept both `"ctrl"` and `"super"` and map to the platform-appropriate modifier. The editor checks `(io.KeyCtrl || io.KeySuper)` so setting either Ctrl or Super works. Use `ImGuiMod_Super` for macOS when `"super": true` is passed.
- Return `{"ok": true, "key": "Z", "modifiers": ["ctrl"]}`.

`mouseClick(args)`:
- Args: `{"x": 400.0, "y": 300.0, "button": 0}` (button: 0=left, 1=right, 2=middle)
- Implementation:
  ```cpp
  ImGuiIO& io = ImGui::GetIO();
  io.AddMousePosEvent(x, y);
  io.AddMouseButtonEvent(button, true);
  io.AddMouseButtonEvent(button, false);
  glfwPostEmptyEvent();
  ```
- Return `{"ok": true, "x": x, "y": y, "button": button}`.

`drag(args)`:
- Args: `{"start_x": 400, "start_y": 300, "end_x": 500, "end_y": 300, "button": 0, "steps": 10}`
- This is the critical one for gizmo diagnosis. Implementation must inject a sequence of events that simulate a real drag but allow per-step state inspection:
  ```cpp
  ImGuiIO& io = ImGui::GetIO();
  int steps = args.value("steps", 10);
  float sx = args["start_x"], sy = args["start_y"];
  float ex = args["end_x"], ey = args["end_y"];
  int button = args.value("button", 0);

  // Move to start position
  io.AddMousePosEvent(sx, sy);
  // Press button
  io.AddMouseButtonEvent(button, true);

  // Interpolate positions
  for (int i = 1; i <= steps; ++i) {
      float t = static_cast<float>(i) / static_cast<float>(steps);
      float cx = sx + (ex - sx) * t;
      float cy = sy + (ey - sy) * t;
      io.AddMousePosEvent(cx, cy);
  }

  // Release button
  io.AddMouseButtonEvent(button, false);
  glfwPostEmptyEvent();
  ```
- IMPORTANT: All these events are queued in ImGui's IO event queue and will be processed across subsequent frames. The drag won't complete in a single frame. Return immediately with a note:
  ```json
  {"ok": true, "queued_events": steps + 3, "note": "Events queued for processing across subsequent frames. Poll inspect.imguizmo_state to observe state changes."}
  ```
- Also support a `"hold": true` mode where the mouse button is NOT released. This allows the diagnostic script to inject a partial drag, inspect state, then send a separate `command.mouse_release` command (add this simple command too — just `io.AddMouseButtonEvent(button, false)`).

Add a `mouseRelease(args)` command:
- Args: `{"button": 0}`
- `io.AddMouseButtonEvent(button, false); glfwPostEmptyEvent();`
- Register as `command.mouse_release` in DebugHarness.

Create `tools/diagnose-gizmo-freeze.py` — a Python script that connects to the running editor via the debug harness Unix socket and systematically exercises gizmo operations while capturing state snapshots.

The script should use the `send_command` pattern from `tools/editor-ctl.py` (copy the socket connection logic). Structure:

```python
#!/usr/bin/env python3
"""Diagnose gizmo and undo/redo freeze in the level editor.

Connects to the running editor via the debug harness socket and:
1. Captures baseline state
2. For each operation type (translate drag, scale drag, undo, redo):
   - Captures state before
   - Executes the operation
   - Waits for frames to process
   - Captures state after
   - Checks for stuck states
3. Outputs a diagnostic report

Usage:
    # Start level editor, select an object, then:
    python3 tools/diagnose-gizmo-freeze.py
    python3 tools/diagnose-gizmo-freeze.py --socket /tmp/pixel-roguelike-editor-1234.sock
"""
```

**Helper functions:**
- `send(sock_path, cmd, args={})` — send command, return response dict
- `capture_state(sock_path)` — send inspect.gizmo_detailed + inspect.imgui_capture + inspect.imguizmo_state, combine into one dict
- `wait_frames(sock_path, n)` — poll inspect.frame_stats n times with small sleep (0.05s) between polls to let frames process
- `check_stuck(state, label)` — check if ImGuizmo::IsUsing is true when mouse is not down, or if WantCaptureMouse is true when no operation is active

**Diagnostic sequence:**

```
1. BASELINE
   - capture_state()
   - Verify an object is selected (abort with helpful message if not)
   - Print: selected objects, current tool, undo/redo state

2. TEST: Translate drag
   - command.set_gizmo {"mode": "Translate"}
   - wait_frames(2)
   - capture state (PRE-DRAG)
   - Compute drag coordinates: use the viewport center area (get mouse pos from state,
     or use hardcoded reasonable values like start=(500,400) end=(600,400))
   - command.drag {"start_x":500, "start_y":400, "end_x":600, "end_y":400, "steps":10, "hold":true}
   - wait_frames(5)
   - capture state (MID-DRAG) — expect IsUsing=true, mouse_left_down=true
   - command.mouse_release {"button": 0}
   - wait_frames(5)
   - capture state (POST-DRAG) — expect IsUsing=false, mouse_left_down=false
   - check_stuck(POST-DRAG)

3. TEST: Scale drag
   - command.set_gizmo {"mode": "Scale"}
   - wait_frames(2)
   - capture state (PRE-DRAG)
   - command.drag {"start_x":500, "start_y":400, "end_x":550, "end_y":400, "steps":10, "hold":true}
   - wait_frames(5)
   - capture state (MID-DRAG)
   - command.mouse_release {"button": 0}
   - wait_frames(5)
   - capture state (POST-DRAG)
   - check_stuck(POST-DRAG)

4. TEST: Undo after gizmo
   - capture state (PRE-UNDO)
   - command.undo {}
   - wait_frames(3)
   - capture state (POST-UNDO) — check IsUsing, WantCaptureMouse, undo stack
   - check_stuck(POST-UNDO)

5. TEST: Redo after undo
   - capture state (PRE-REDO)
   - command.redo {}
   - wait_frames(3)
   - capture state (POST-REDO)
   - check_stuck(POST-REDO)

6. TEST: Rapid undo/redo cycle (3 times)
   - For i in range(3): undo, wait, capture
   - For i in range(3): redo, wait, capture
   - Check final state for stuck

7. TEST: Drag that leaves viewport (simulate mouse going outside)
   - command.drag from (500,400) to (0,400) or off-screen coords
   - wait_frames(5)
   - capture state — this is the key freeze scenario
```

**Stuck state detection logic:**
- `IsUsing=true AND mouse_left_down=false` → gizmo stuck in drag mode
- `WantCaptureMouse=true AND IsUsing=false AND IsOver=false` → ImGui thinks it owns mouse but nothing is active
- `can_undo changed unexpectedly` → undo stack corruption
- `selected_count=0 after undo` → selection pruning issue

Make the script executable (`#!/usr/bin/env python3`).
