<objective>
Diagnose why QuestDoorsPack FBX doors render at ~2x wall height and fix the scene scale.

Purpose: The doors were blindly set to scale 0.25 which may not be correct. We need to measure the actual model dimensions after Assimp's cm-to-m conversion (`AI_CONFIG_FBX_CONVERT_TO_M = true`) to compute the exact scale factor. Unity asset packs typically author FBX in cm with a 100x root scale that Unity silently absorbs — Assimp's cm-to-m flag converts vertices but may not collapse the root transform node, leading to double-scaling.

Output: A diagnostic test that prints AABB dimensions, and a corrected scene file.
</objective>

**Key measurements from the codebase:**
- `prison_wall_door` opening: 0.9m wide (X: -0.45 to +0.45), 2.1m tall (Y: 0 to 2.1)
- `prison_wall` tile: 2m wide x 4m tall (walls are 4m, room is 4m Y)
- Current scene door scale: 0.25 uniform (blind guess)
- `AI_CONFIG_FBX_CONVERT_TO_M = true` is set on both `loadRaw` and `loadRawMulti` paths
- Assimp import flags include `aiProcess_PreTransformVertices` which flattens the node hierarchy into vertex positions

**Important Assimp behavior:** `aiProcess_PreTransformVertices` bakes ALL node transforms (including root scale) into vertex positions. Combined with `AI_CONFIG_FBX_CONVERT_TO_M`, the resulting vertex positions should already be in meters. If the model still appears 2x too large, it means the FBX was authored at ~4m height in its native units (i.e., the 3D artist modeled a ~400cm door, which is indeed realistic for some asset packs that model oversized "game-ready" doors).
