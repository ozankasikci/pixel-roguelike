# Quick Task 260402-1l5: Investigate and Fix QuestDoorsPack FBX Door Scale

**One-liner:** Measured FBX AABB via Assimp (doors are ~9.2m tall, not 2m); corrected scene scale from 0.25 to 0.21 to properly fit the 2.1m prison_wall_door opening.

## What Was Done

### Task 1 — Diagnostic Test

Created `tests/engine/test_questdoor_scale.cpp` following the `test_model_loader.cpp` pattern. The test loads each of the three door FBX files via `ModelLoader::loadRaw()` and computes the AABB (min/max over all vertex positions). It prints dimensions and recommended scale factors for a 2.0m tall x 0.85m wide target fit.

Registered in `tests/engine/CMakeLists.txt` as `test_questdoor_scale` with `engine_rendering` library.

**Actual measurements from running the test:**

| Model | Width (X) | Height (Y) | scale_by_height | scale_by_width | Recommended |
|-------|-----------|------------|-----------------|----------------|-------------|
| SM_DoorA | 4.0556m | 9.2150m | 0.2170 | 0.2096 | **0.21** |
| SM_DoorC | 4.0483m | 9.1616m | 0.2183 | 0.2100 | **0.21** |
| SM_DoorD | 4.0709m | 9.1625m | 0.2183 | 0.2088 | **0.21** |

**Root cause:** QuestDoorsPack FBX models are authored at ~9.2m height (the pack targets Unity which silently absorbs the root scale). Assimp's `AI_CONFIG_FBX_CONVERT_TO_M=true` with `aiProcess_PreTransformVertices` correctly bakes all node transforms including the 100x root scale into vertex positions — so the 9.2m is the true native authored height in game-unit meters. The old scale of 0.25 produced doors approximately 2.3m tall, visibly taller than the 2.1m wall opening.

### Task 2 — Scene File Fix

Updated `assets/scenes/initial_scene.scene` — replaced the blind guess of `0.25 0.25 0.25` with `0.21 0.21 0.21` on all three door mesh entries. Added a comment block documenting the pack's native scale convention and the source of the 0.21 value.
