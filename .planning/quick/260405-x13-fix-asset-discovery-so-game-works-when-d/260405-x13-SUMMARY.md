# Quick Plan 260405-x13: Fix Asset Discovery Summary

Rewrote projectRoot() with 5-strategy search order and spdlog diagnostic logging so the game finds assets when distributed outside the project tree, including macOS .app bundles.

## What Changed

The `projectRoot()` function in `PathUtils.cpp` was updated from a 2-strategy search (CWD, exe walk-up) to a 5-strategy search with diagnostic logging on every path:

1. **PIXEL_ROGUELIKE_ROOT env var** -- highest priority override for CI, testing, and custom installs
2. **CWD walk-up** -- unchanged behavior, kept second for developer ergonomics (running from project root)
3. **macOS .app bundle detection** -- new; parses exe path for `.app/Contents/MacOS`, checks `Contents/Resources/assets/`
4. **Exe-relative walk-up** -- existing logic, now applies `fs::weakly_canonical()` on macOS for symlink resolution
5. **CWD fallback** -- last resort, now emits a warning log so failures are diagnosable

Added `#include <spdlog/spdlog.h>` and `#include <cstdlib>` (for `std::getenv`). No changes to the public API (`PathUtils.h`), `findProjectRoot()`, `resolveProjectPath()`, or `hasValidProjectRoot()`.
