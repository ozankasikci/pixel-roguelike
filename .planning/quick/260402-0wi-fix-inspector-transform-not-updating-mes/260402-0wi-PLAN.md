1. In EditorPreviewWorld.h, add public method declaration after syncLights:
   `void syncTransforms(const EditorSceneDocument& document);`

2. In EditorPreviewWorld.cpp, implement syncTransforms following the exact pattern of syncMaterials and syncLights. The method should:
   - Iterate all entities that have a TransformComponent using `registry_.view<TransformComponent>()`
   - For each entity, look up its owner document object ID via `ownerMap_`
   - Call `document.findObject(ownerIt->second)` to get the EditorSceneObject
   - Use `decomposeTransformMatrix(document.worldTransformMatrix(object->id), position, rotation, scale)` to extract the current document transform
   - Handle each object kind differently:
     - **Mesh**: Update `transform.position`, `transform.rotation`, `transform.scale` from decomposed values
     - **BoxCollider**: Update the `StaticColliderComponent` position, rotation, and halfExtents (scale * 0.5, clamped to 0.001 min) -- must get<StaticColliderComponent> for the entity
     - **CylinderCollider**: Update `StaticColliderComponent` position, rotation, radius ((abs(scale.x)+abs(scale.z))*0.25, min 0.001), halfHeight (abs(scale.y)*0.5, min 0.001)
     - **Light**: Update `transform.position` (lights only have position from transform, the rest is synced by syncLights)
     - **Archetype**: Update `transform.position` and `transform.rotation.y` (yawDegrees only, matching rebuild logic)
     - **PlayerSpawn**: Skip (no ECS entity created)
   - After the iteration loop, call `rebuildBounds()` to update objectBounds_ and sceneBounds_ so selection framing and hit-testing remain correct.

   Note: The decomposeTransformMatrix helper is already defined in the anonymous namespace of EditorPreviewWorld.cpp, so it is directly usable.
