**Fix 1a — AssetCache: Add overloaded findMeshCache/writeMeshCache that accept separate source file path and cache label.**

The current `findMeshCache(filepath)` and `writeMeshCache(filepath, ...)` use `filepath` for both hashing (reading file contents) AND constructing the cache filename stem. When `loadFromFileMulti` passes `resolvedPath + "#" + entry.name` (e.g., `/full/path/country_house.fbx#OldHouseMapWood02`), `hashFileContents` fails to open it as a file and returns 0, causing early-return on both find and write.

Add two new overloads to AssetCache (keep existing single-arg versions unchanged for backward compat):

In `AssetCache.h`, add:
```cpp
static std::optional<CachedMeshData> findMeshCache(const std::string& sourceFilePath,
                                                    const std::string& cacheLabel);
static void writeMeshCache(const std::string& sourceFilePath,
                           const std::string& cacheLabel,
                           const std::vector<float>& interleavedVertices,
                           const std::vector<uint32_t>& indices,
                           const glm::vec3& aabbMin,
                           const glm::vec3& aabbMax);
```

In `AssetCache.cpp`, implement the new overloads:
- `findMeshCache(sourceFilePath, cacheLabel)`: Call `hashFileContents(sourceFilePath)` to get the content hash of the actual FBX file. Use `cacheLabel` (not sourceFilePath) as the stem for cache filename construction: `cacheLabel + "_" + toHexString(sourceHash) + ".mesh.bin"`. Otherwise identical logic to the existing single-arg version.
- `writeMeshCache(sourceFilePath, cacheLabel, ...)`: Same pattern — hash `sourceFilePath`, use `cacheLabel` as stem.

**Fix 1b — MeshLibrary::loadFromFileMulti: Use the new two-arg AssetCache overloads and add early-exit.**

At the top of `loadFromFileMulti`, before calling `ModelLoader::loadRawMulti`, add an early-exit check: if ALL expected submeshes are already registered in `meshes_` (check `meshes_.count(baseName + "#" + ...)` — but we don't know submesh names yet without parsing). Instead, use a simpler guard: if `meshes_` already contains any key starting with `baseName + "#"`, return early. This handles the `bootstrapRuntimeMeshLibrary` double-call case. Implementation:

```cpp
// Early-exit if submeshes already registered (avoids re-parsing FBX)
bool alreadyLoaded = false;
const std::string prefix = baseName + "#";
for (const auto& [name, mesh] : meshes_) {
    if (name.compare(0, prefix.size(), prefix) == 0) {
        alreadyLoaded = true;
        break;
    }
}
if (alreadyLoaded) {
    return;
}
```

Then in the per-submesh loop, change the cache calls from:
```cpp
auto cached = AssetCache::findMeshCache(cacheKey);  // cacheKey = resolvedPath + "#" + entry.name
```
to:
```cpp
auto cached = AssetCache::findMeshCache(resolvedPath, baseName + "_" + entry.name);
```
And change the write call from:
```cpp
AssetCache::writeMeshCache(cacheKey, interleaved, raw.indices, ...);
```
to:
```cpp
AssetCache::writeMeshCache(resolvedPath, baseName + "_" + entry.name, interleaved, raw.indices, ...);
```

This hashes the actual `country_house.fbx` file (which exists and can be read) and uses `country_house_OldHouseMapWood02` as the cache filename stem (unique per submesh, no path separators).

<task type="auto">
  <name>Task 2: Add disk caching for file-based textures in MaterialTextureLibrary</name>
  <files>src/game/rendering/MaterialTextureLibrary.cpp</files>
  <action>
In `MaterialTextureLibrary::ensureTextureSet`, the `else` branch (lines 312-326) loads file-based textures with `createRGBA8FromFile`/`createR8FromFile` every launch with the comment "File-based textures: not cached per design doc (diminishing returns)". With 206 MB of 4K PNGs this is now the dominant cost.

Replace the file-based texture loading block (lines 312-326) with a caching approach that mirrors the procedural texture caching pattern already used above it. The file-based textures use the same `TextureSet` structure and can use the same `AssetCache::findTextureCache`/`writeTextureCache` methods.

The implementation:

1. Compute a `paramHash` for file-based textures by hashing the texture key string (same approach as procedural: `AssetCache::hashBytes(key.data(), key.size())`). The `key` already encodes all file paths via `textureKeyFor()`, so if any texture path changes, the hash changes.

2. Try loading all 4 texture channels from cache (albedo, normal, roughness, ao) — same pattern as lines 272-285 for procedural textures. If all present channels have cache hits, create GL textures from cached pixel data and return early.

3. On cache miss, load textures from files using stb_image (as before), but also read back the pixel data and write it to the cache. The problem: `createRGBA8FromFile` loads pixels, creates GL texture, and discards the CPU-side data. We need the pixel data for cache writing.

   Replace the direct `createRGBA8FromFile`/`createR8FromFile` calls with inline stb_image loading that keeps pixel data around:

   ```cpp
   // File-based textures: load with caching
   uint64_t paramHash = AssetCache::hashBytes(key.data(), key.size());

   // Try cache first
   bool allCached = true;
   auto cachedAlbedo = !resolved.albedoMapPath.empty()
       ? AssetCache::findTextureCache(key + "_file_albedo", paramHash)
       : std::nullopt;
   auto cachedNormal = !resolved.normalMapPath.empty()
       ? AssetCache::findTextureCache(key + "_file_normal", paramHash)
       : std::nullopt;
   auto cachedRoughness = !resolved.roughnessMapPath.empty()
       ? AssetCache::findTextureCache(key + "_file_roughness", paramHash)
       : std::nullopt;
   auto cachedAo = !resolved.aoMapPath.empty()
       ? AssetCache::findTextureCache(key + "_file_ao", paramHash)
       : std::nullopt;

   // Check if all requested channels have cache hits
   if ((!resolved.albedoMapPath.empty() && !cachedAlbedo) ||
       (!resolved.normalMapPath.empty() && !cachedNormal) ||
       (!resolved.roughnessMapPath.empty() && !cachedRoughness) ||
       (!resolved.aoMapPath.empty() && !cachedAo)) {
       allCached = false;
   }

   if (allCached) {
       if (cachedAlbedo) textures.albedo.createRGBA8(cachedAlbedo->width, cachedAlbedo->height, cachedAlbedo->pixels);
       if (cachedNormal) textures.normal.createRGBA8(cachedNormal->width, cachedNormal->height, cachedNormal->pixels);
       if (cachedRoughness) textures.roughness.createR8(cachedRoughness->width, cachedRoughness->height, cachedRoughness->pixels);
       if (cachedAo) textures.ao.createR8(cachedAo->width, cachedAo->height, cachedAo->pixels);
   } else {
       // Cache miss: load from files, write cache
       if (!resolved.albedoMapPath.empty()) {
           textures.albedo.createRGBA8FromFile(resolveProjectPath(resolved.albedoMapPath));
       }
       if (!resolved.normalMapPath.empty()) {
           textures.normal.createRGBA8FromFile(resolveProjectPath(resolved.normalMapPath));
       }
       if (!resolved.roughnessMapPath.empty()) {
           textures.roughness.createR8FromFile(resolveProjectPath(resolved.roughnessMapPath));
       }
       if (!resolved.aoMapPath.empty()) {
           textures.ao.createR8FromFile(resolveProjectPath(resolved.aoMapPath));
       }

       // Write loaded textures to cache for next launch
       // Re-read pixel data from files for cache writing (stb_image is fast for sequential re-reads,
       // cheaper than refactoring Texture2D to expose pixel data)
       auto writeFileTextureCache = [&](const std::string& mapPath, const std::string& suffix, int reqChannels) {
           if (mapPath.empty()) return;
           std::string resolved_path = resolveProjectPath(mapPath);
           int w = 0, h = 0, ch = 0;
           stbi_uc* px = stbi_load(resolved_path.c_str(), &w, &h, &ch, reqChannels);
           if (px) {
               size_t count = static_cast<size_t>(w) * h * reqChannels;
               std::vector<uint8_t> pixels(px, px + count);
               stbi_image_free(px);
               AssetCache::writeTextureCache(key + suffix, paramHash, pixels,
                   static_cast<uint16_t>(w), static_cast<uint16_t>(h), static_cast<uint8_t>(reqChannels));
           }
       };
       writeFileTextureCache(resolved.albedoMapPath, "_file_albedo", 4);
       writeFileTextureCache(resolved.normalMapPath, "_file_normal", 4);
       writeFileTextureCache(resolved.roughnessMapPath, "_file_roughness", 1);
       writeFileTextureCache(resolved.aoMapPath, "_file_ao", 1);
   }
   ```

   Add `#include <stb_image.h>` at the top of MaterialTextureLibrary.cpp if not already present.

   **Why re-read for cache write instead of refactoring Texture2D:** The first load creates the GL texture (critical for rendering). Re-reading the same files for cache writing is a one-time cost on cold cache. Refactoring Texture2D to expose pixel data would touch more files and change the API surface for marginal benefit. On warm cache, files are not re-read at all.

   **TextureCacheHeader width/height are uint16_t (max 65535).** 4K textures are 4096x4096, well within range.

   Update the comment from "File-based textures: not cached per design doc (diminishing returns)" to "File-based textures: cached to disk (206 MB of PNGs makes caching essential)".
