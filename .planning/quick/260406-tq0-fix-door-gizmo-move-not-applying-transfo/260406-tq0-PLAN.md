**Root cause:** `syncTransforms()` SingleDoor case (line 390-393) sets ALL entities owned by a door object to `position` (root position) and `rotation.y`. But a SingleDoor spawns two entities during `rebuild()` -- a frame mesh at `rootPosition` and a door leaf mesh at `hingeWorldPos` (root + rotated hinge offset). Both map to the same owner ID in `ownerMap_`. The sync has no way to tell them apart, so the leaf gets the root position instead of its offset position. The visual result: gizmo moves the document data but the preview doesn't update correctly.

**Fix (3 changes):**

1. **EditorPreviewWorld.h** -- Add a marker tag component struct at the top of the file (before the class):
```cpp
struct EditorDoorLeafTag {};
```

2. **EditorPreviewWorld.cpp, rebuild(), SingleDoor case** (around line 260) -- After the second `builder.addMesh()` call for the door leaf, capture the returned entity and tag it:
```cpp
entt::entity leafEntity = builder.addMesh(placement.doorMeshName, ...);
if (leafEntity != entt::null) {
    registry_.emplace<EditorDoorLeafTag>(leafEntity);
}
```
The first `builder.addMesh()` for the frame does NOT get tagged (it remains un-tagged, which means "frame").

3. **EditorPreviewWorld.cpp, syncTransforms(), SingleDoor case** (line 390-393) -- Replace the simple position assignment with proper hinge offset computation for leaf entities:
```cpp
case EditorSceneObjectKind::SingleDoor: {
    const auto& door = std::get<LevelSingleDoorPlacement>(object->payload);
    const float yawRad = glm::radians(rotation.y);
    if (registry_.all_of<EditorDoorLeafTag>(entity)) {
        // Door leaf: recompute hinge offset from root position
        constexpr float kDoorScale = 0.22f;
        const glm::vec3 localHingeOffset(-0.45f, 0.0f, 0.04f);
        const glm::vec3 hingeWorldPos = position + glm::vec3(
            localHingeOffset.x * std::cos(yawRad) - localHingeOffset.z * std::sin(yawRad),
            0.0f,
            localHingeOffset.x * std::sin(yawRad) + localHingeOffset.z * std::cos(yawRad));
        transform.position = hingeWorldPos;
        transform.rotation.y = rotation.y;
        transform.scale = glm::vec3(kDoorScale);
    } else {
        // Door frame: at root position
        constexpr float kDoorScale = 0.22f;
        transform.position = position;
        transform.rotation.y = rotation.y;
        transform.scale = glm::vec3(kDoorScale);
    }
    break;
}
```

Note: The `position` and `rotation` variables are already decomposed from `document.worldTransformMatrix(object->id)` earlier in the method (line 338-341). The `position` IS the rootPosition (from `localTransformMatrix` which uses `makeTransformMatrix(p.rootPosition, ...)`), and `rotation.y` is `doorYawDegrees`. The hinge offset math must match the rebuild code exactly (same `localHingeOffset` values and rotation formula).

Also note: `scale` from decompose will be (1,1,1) since `localTransformMatrix` uses scale (1,1,1) for SingleDoor. The visual scale is `kDoorScale` (0.22), which is applied in rebuild but NOT stored in the transform component by the existing sync code. This is likely also contributing to visual issues. Set `transform.scale = glm::vec3(kDoorScale)` for both frame and leaf in the sync. Also update the MeshComponent modelOverride if applicable -- check if the addMesh path sets `useModelOverride = true` on the MeshComponent (it does, per LevelBuilder::addMesh line 126). If so, also update `mesh.modelOverride` in the sync:
```cpp
if (registry_.all_of<MeshComponent>(entity)) {
    auto& mesh = registry_.get<MeshComponent>(entity);
    if (mesh.useModelOverride) {
        mesh.modelOverride = makeModelMatrix(transform.position, glm::vec3(kDoorScale), glm::vec3(0.0f, rotation.y, 0.0f));
    }
}
```
Do this for both the frame and leaf branches, using their respective positions.
