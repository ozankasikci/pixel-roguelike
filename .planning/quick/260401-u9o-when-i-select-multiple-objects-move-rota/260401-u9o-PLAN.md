  <action>
Rewrite `applyGizmoToSelectedObject` in EditorViewportInteraction.cpp to handle both single and multi-selection. The function signature stays the same (no header change needed for this). The algorithm:

**1. Guard clause changes:**
- Change `if (selectedIds.size() != 1 || ui.playPreview)` to `if (selectedIds.empty() || ui.playPreview)`.

**2. Single-object path (selectedIds.size() == 1):**
- Keep the existing single-object logic exactly as-is. It handles lights (directional has special anchor via scene bounds), player spawn (stripped rotation columns), and mesh/collider/archetype objects. Do NOT change the single-object behavior.

**3. Multi-object path (selectedIds.size() > 1):**

Compute centroid:
```cpp
glm::vec3 centroid(0.0f);
int count = 0;
for (auto id : selectedIds) {
    const EditorSceneObject* obj = document.findObject(id);
    if (!obj) continue;
    centroid += editorSceneObjectAnchor(*obj);
    ++count;
}
if (count == 0) return false;
centroid /= static_cast<float>(count);
```

Build a virtual gizmo matrix at the centroid with identity rotation and unit scale:
```cpp
glm::mat4 gizmoMatrix = glm::translate(glm::mat4(1.0f), centroid);
```

Call `manipulateEditorGizmo` with this gizmoMatrix. If it returns false (user not dragging), return false.

**After manipulation, compute and apply the delta transform to each selected object:**

For **Translate** (`ui.tool == EditorTransformTool::Translate`):
- Extract new position from manipulated gizmoMatrix column 3.
- Compute `glm::vec3 delta = newPosition - centroid`.
- If snapping enabled, snap the delta components.
- For each selected object: get its `worldTransformMatrix`, add delta to its translation column (column 3), call `applyWorldTransform` with the modified matrix.
- Special handling for lights: for non-directional lights, add delta directly to `light.position`. For directional lights, skip translation (they have no position). Mark the document dirty for light objects.

For **Rotate** (`ui.tool == EditorTransformTool::Rotate`):
- Extract the rotation from the manipulated gizmoMatrix. Since the gizmo was placed at centroid with identity rotation, the manipulated matrix encodes: `T(centroid) * R(delta) * S(1)`. So `deltaRotation = glm::mat4(glm::mat3(gizmoMatrix))` — extract the 3x3 rotation portion.
- Actually, more robustly: `glm::mat4 deltaTransform = gizmoMatrix * glm::inverse(glm::translate(glm::mat4(1.0f), centroid))`. This gives the pure rotation matrix applied by the user.
- For each selected object:
  - Get the object's world anchor position.
  - Compute the offset from centroid: `offset = anchor - centroid`.
  - Rotate the offset: `newOffset = glm::vec3(deltaTransform * glm::vec4(offset, 1.0f))`.
  - New anchor = `centroid + newOffset` (but this is already in `newOffset` since deltaTransform includes translation=0 at origin).
  - For mesh/collider/archetype: get the current `worldTransformMatrix`. Apply the rotation and new position: `newWorld = glm::translate(glm::mat4(1.0f), centroid + newOffset - offset) * deltaTransform * currentWorld`. Wait, simpler approach:
    - `newWorld = glm::translate(glm::mat4(1.0f), centroid) * deltaTransform * glm::translate(glm::mat4(1.0f), -centroid) * currentWorld`
    - This translates to centroid-origin, applies the rotation, then translates back. This correctly rotates both the object's position and its orientation around the centroid.
  - Call `applyWorldTransform(id, newWorld)`.
  - For lights (non-directional): compute new position the same way. For spot lights, also rotate the direction vector. For directional lights: rotate the direction vector only.

For **Scale** (`ui.tool == EditorTransformTool::Scale`):
- Same pattern as rotate but with scale factor. Extract scale from gizmoMatrix.
- `deltaTransform = glm::translate(glm::mat4(1.0f), centroid) * glm::scale(glm::mat4(1.0f), scaleFactors) * glm::translate(glm::mat4(1.0f), -centroid)`
- For each selected object: `newWorld = deltaTransform * currentWorld` — this scales positions relative to centroid and scales the object itself.
- Actually reuse the same generic formula: `newWorld = glm::translate(glm::mat4(1.0f), centroid) * localDelta * glm::translate(glm::mat4(1.0f), -centroid) * currentWorld` where `localDelta` is the scale portion of the gizmo change.
- Call `applyWorldTransform(id, newWorld)`.

**Unified delta approach (PREFERRED — simpler implementation):**

Instead of branching by tool type, use a single unified approach:
```cpp
// The gizmo started at gizmoMatrixBefore = translate(centroid)
// After manipulation it became gizmoMatrixAfter
// The delta in world space: deltaTransform = gizmoMatrixAfter * inverse(gizmoMatrixBefore)
glm::mat4 before = glm::translate(glm::mat4(1.0f), centroid);
glm::mat4 deltaWorld = gizmoMatrix * glm::inverse(before);
// This gives us: deltaWorld = T(centroid) * R * S * T(-centroid)
// Which is NOT what we want. We want to transform objects around centroid.

// Correct: pivot transform
// newWorld = T(centroid) * localDelta * T(-centroid) * objectWorld
// where localDelta = T(-centroid) * gizmoMatrix = inverse(before) * gizmoMatrix
glm::mat4 localDelta = glm::inverse(before) * gizmoMatrix;
```

Then for each object:
```cpp
glm::mat4 objectWorld = document.worldTransformMatrix(id);
glm::mat4 newWorld = before * localDelta * glm::inverse(before) * objectWorld;
document.applyWorldTransform(id, newWorld);
```

This single formula handles translate (localDelta has translation), rotate (localDelta has rotation), and scale (localDelta has scale) uniformly. No tool-specific branching needed.

**Light objects in multi-select need special handling** because `applyWorldTransform` only updates `light.position` from column 3 and does not rotate the direction. For multi-select simplicity, handle lights by:
- Non-directional lights: the unified formula works via `applyWorldTransform` for position. For spot lights with direction, additionally extract rotation from `localDelta` and rotate `light.direction`.
- Directional lights: skip position change. If rotating, rotate `light.direction` by `localDelta`'s rotation portion.
- Actually, the simplest correct approach: after calling the unified `applyWorldTransform` for non-light objects, handle lights separately:
  ```cpp
  if (object->kind == EditorSceneObjectKind::Light) {
      auto& light = std::get<LevelLightPlacement>(object->payload);
      glm::vec3 anchor = editorSceneObjectAnchor(*object);
      glm::vec3 newAnchor = glm::vec3(before * localDelta * glm::inverse(before) * glm::vec4(anchor, 1.0f));
      glm::mat3 rotPart(localDelta); // rotation portion
      if (light.type != LightType::Directional) {
          light.position = newAnchor;
      }
      if (light.type == LightType::Spot || light.type == LightType::Directional) {
          light.direction = safeNormalize(rotPart * light.direction, light.direction);
      }
      document.markSceneDirty();
  }
  ```

For PlayerSpawn: `applyWorldTransform` already extracts only position from column 3, which is correct.

**Important: The function must return true when manipulation occurred** so `previewDirty` is set in main.cpp. The existing undo/redo capture (gizmoBeforeState / gizmoCommand) captures the entire document state BEFORE the gizmo starts, so multi-object undo works automatically.

**Snapping for multi-select:** The gizmo already handles snapping internally within `manipulateEditorGizmo` (it passes snap values to ImGuizmo). For single-object, additional post-snap was applied. For multi-select, rely on ImGuizmo's built-in snapping only — do NOT apply post-snap to individual objects (that would snap each to grid individually, losing relative positions).

**Header change:** The function signature in EditorViewportInteraction.h stays the same. No changes needed there.

**Include:** Add `#include "engine/core/MathUtils.h"` if not already present (it is already included for `safeNormalize` and `makeModelMatrix`).
