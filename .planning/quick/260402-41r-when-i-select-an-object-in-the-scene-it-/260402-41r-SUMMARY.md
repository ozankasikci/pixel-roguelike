# Quick Task 260402-41r: Outliner Auto-Scroll to Viewport Selection

**One-liner:** Viewport object selection now scrolls and auto-expands the outliner panel to reveal the selected item, using a one-shot `scrollToSelection` flag consumed once per frame.

## What Was Built

When a user clicks an object in the 3D viewport, the outliner/hierarchy panel automatically:
1. Expands any collapsed ancestor group nodes so the selected item is reachable
2. Scrolls to center the selected item in the outliner

Outliner-originated selections and deselection (clicking empty space) do not trigger the scroll.

## Implementation Details

### EditorUiState (LevelEditorUi.h)

Added `bool scrollToSelection = false;` next to `frameSelectionRequested`.

### main.cpp — three trigger sites

Set `ui.scrollToSelection = true` after:
- `applySelectionHit()` (viewport ray-cast selection, non-empty hit)
- `commitPlacement()` via drag-drop into viewport
- `commitPlacement()` via click with placement mode active

Deselection (empty-space click) and gizmo operations do not set the flag.

### EditorOutlinerPanel.cpp — consume site

Before the `renderNode` lambda:
- If `scrollToSelection` is set, walks up `document.parentObjectId()` for each selected ID, collecting all ancestor IDs into `expandForScroll` set
- Initializes `scrolledThisFrame = false`

Inside `renderNode`:
- Calls `ImGui::SetNextItemOpen(true, ImGuiCond_Always)` for nodes in `expandForScroll`
- After `TreeNodeEx`, calls `ImGui::SetScrollHereY(0.5f)` on the first selected node (guarded by `scrolledThisFrame`)

After all root nodes rendered:
- Resets `ui.scrollToSelection = false` (one-shot consumed)
