<objective>
Add multi-submesh FBX loading so models with multiple materials (like country_house.fbx with 5 materials across 22 submeshes) can have different materials applied to each material group.

Purpose: The country_house.fbx currently loads as a single merged mesh, forcing one material for the entire building. Splitting by material group enables wood, walls, glass, and window frames to each use distinct materials.

Output: New parallel `loadRawMulti()` API on AssimpLoader/ModelLoader, `loadFromFileMulti()` on MeshLibrary, updated country_house.scene with 5 per-material mesh entries.
</objective>

**2. Add loadRawMulti to AssimpLoader** (.h and .cpp):

Declaration in AssimpLoader.h:
```cpp
static std::vector<NamedRawMeshData> loadRawMulti(const std::string& filepath);
```
Add `#include <vector>` to the header if needed.

Implementation in AssimpLoader.cpp -- add a new file-local helper `loadGroupedByMaterial` that:
- Iterates `scene->mMeshes[0..mNumMeshes-1]`
- For each mesh, reads `mMaterialIndex` and looks up the material name via `scene->mMaterials[idx]->GetName()` (returns `aiString`, use `.C_Str()` to get const char*)
- If material name is empty, use `"material_" + std::to_string(materialIndex)` as fallback
- Groups submeshes into a `std::unordered_map<unsigned, std::vector<unsigned>>` keyed by material index, values are mesh indices
- For each material group, merges the submeshes (same logic as loadMergedRaw but only for meshes in that group) -- reuse the per-mesh vertex/index extraction loop from loadMergedRaw, applying the same generateSmoothNormals/generateProjectedUVs/generateTangents fixups per part before merging
- Returns `std::vector<NamedRawMeshData>` sorted by material name for deterministic ordering

The `loadRawMulti` method itself:
- Creates Assimp::Importer, calls ReadFile with the same kAssimpImportFlags
- Validates scene has meshes
- Calls loadGroupedByMaterial
- Logs: "AssimpLoader::loadRawMulti: loaded '{filepath}' ({N} material groups)"
- Returns the vector (empty on error)

**3. Add loadRawMulti to ModelLoader** (.h and .cpp):

Declaration:
```cpp
static std::vector<NamedRawMeshData> loadRawMulti(const std::string& filepath);
```

Implementation:
- For `.fbx` extension: delegate to `AssimpLoader::loadRawMulti(filepath)`
- For `.glb`/`.gltf`: return a single-element vector with name = file stem (from `std::filesystem::path(filepath).stem().string()`), mesh = `GltfLoader::loadRaw(filepath)`. This preserves backward compat -- glTF path just wraps the existing single-mesh result.
- For unsupported extensions: log error, return empty vector.

**4. Add loadFromFileMulti to MeshLibrary** (.h and .cpp):

Declaration in MeshLibrary.h (after `loadFromFile`):
```cpp
void loadFromFileMulti(const std::string& baseName, const std::string& filepath);
```

Implementation in MeshLibrary.cpp:
- Resolve the path via `resolveProjectPath(filepath)`
- Call `ModelLoader::loadRawMulti(resolvedPath)`
- If result is empty, log error and return
- For each `NamedRawMeshData` in the result:
  - Construct mesh name as `baseName + "#" + entry.name`
  - Check disk cache using `AssetCache::findMeshCache(resolvedPath + "#" + entry.name)` -- the `#suffix` ensures no collision with single-mesh cache entries
  - If cache hit: register from cache (same pattern as loadFromFile)
  - If cache miss: create `Mesh` from raw data, build interleaved data, call `AssetCache::writeMeshCache(resolvedPath + "#" + entry.name, ...)`, then register
  - Call `registerMesh(meshName, std::move(mesh))`
- Log: "MeshLibrary: registered {N} submeshes from '{filepath}' as '{baseName}#...'"

IMPORTANT: Do NOT modify existing `loadRaw()`, `loadFromFile()`, `registerFileAlias()`, or `load()` methods. The new multi-mesh API is purely additive.
