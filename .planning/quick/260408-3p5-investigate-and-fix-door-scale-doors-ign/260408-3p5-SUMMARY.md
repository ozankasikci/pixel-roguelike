# Quick Task 260408-3p5: Add Scale Support to Door Groups

**One-liner:** Door group scale field added end-to-end — data model, parse/serialize, hierarchy resolution, spawner leaf multiply, collider scaling, and editor inspector DragFloat3.

## What Was Built

Door groups (`door_group` scene records) were the only entity type that could not be scaled. This task added a complete `glm::vec3 scale{1.0f}` field through the entire pipeline:

1. **Data model** (`LevelDef.h`): Added `glm::vec3 scale{1.0f}` to `LevelDoorPlacement` after the `position` field, matching the pattern of `LevelMeshPlacement` and `LevelGroupNode`.

2. **Parser** (`DoorSerializer.cpp`): New `else if` branch handles `scale sx sy sz` optional token in `parseDoorGroup()`, inserted after `interact_dot` and before `locked`.

3. **Serializer** (`DoorSerializer.cpp`): Writes `scale x y z` in `serializeDoorGroups()` only when non-default, preserving backward compatibility with existing scene files.

4. **Hierarchy resolution** (`LevelDef.cpp`):
   - `localMatrixFor` DoorGroup case: passes `dg.scale` instead of hardcoded `glm::vec3(1.0f)`
   - Decompose DoorGroup case: stores scale back with `glm::max(scale, glm::vec3(0.01f))` clamp

5. **Spawner** (`DoorSpawner.cpp`): Computes `combinedScale = m.scale * group.scale` and uses it for `addMesh`, `makePivotLeafModel`, `DoorLeafComponent.closedScale`. Collider half-extents multiplied by `group.scale`.

6. **Editor inspector** (`DoorGroupInspector.cpp`): Scale DragFloat3 row added between Position and Yaw, step 0.01f, min 0.01f, with full undo/redo support via `trackLastItemCommand`.

7. **Tests** (`test_door_group_position.cpp`): Two new test sections:
   - Section 5: Verifies `resolveLevelHierarchy` preserves a `scale(2,2,2)` door placement
   - Section 6: Verifies different scales produce different model matrices from `makePivotLeafModel`
