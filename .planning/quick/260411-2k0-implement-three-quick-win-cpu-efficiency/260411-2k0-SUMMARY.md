**Viewport dirty flag, conditional hover picking, and adaptive VSync reduce idle CPU/GPU usage in the level editor**

## Accomplishments
- Edit-mode 3D viewport re-render is skipped when camera, scene, selections, UI toggles, and viewport size are all unchanged -- FBO texture persists and ImGui::Image displays the last frame
- Hover picking (ray-cast against scene objects) only runs when mouse position changes; cached hover result is reused on stationary frames
- VSync is disabled during idle and unfocused states so glfwWaitEventsTimeout controls frame pacing without additional GPU blocking; re-enabled during continuous rendering (play preview, ImGui interaction) for tear-free display

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Added right-mouse-button and mouse-wheel to viewport dirty triggers**
- **Found during:** Task 1 (implementation analysis)
- **Issue:** Plan's dirty check did not include right-mouse-button press or scroll wheel. Camera fly mode uses WASD while RMB is held; if the user holds RMB without moving the mouse, MouseDelta is zero and camera position hasn't changed yet, so the render block (including updateEditorFlyCamera) would be skipped entirely, preventing camera movement. Similarly, scroll-wheel zoom would be missed.
- **Fix:** Added `|| (io.MouseWheel != 0.0f) || (glfwGetMouseButton(window.handle(), GLFW_MOUSE_BUTTON_RIGHT) == GLFW_PRESS)` to the viewportDirty conditions
- **Files modified:** apps/level_editor/main.cpp
- **Verification:** Build succeeds; logical analysis confirms all camera interaction modes now trigger dirty
- **Committed in:** 4d254f6 (Task 1 commit)

## Post-Executor Fixes (manual)

Three critical issues found via CPU profiling (`sample` tool) after executor commit:

1. **Play preview fallthrough bug** — Adding `&& viewportDirty` to edit-mode condition caused clean frames to fall through to the else-if play preview renderer (49% of idle CPU). Fixed by adding `&& ui.playPreview` to the else-if guard.

2. **WantCaptureMouse always true** — `ImGui::GetIO().WantCaptureMouse` is true whenever the cursor is over any ImGui panel (always), so `needsContinuousRendering` was always true and idle timeouts never activated. Replaced with `cameraAnim.active`.

3. **Mouse-over-panel re-renders** — Any mouse movement triggered full viewport re-render with shadows. Fixed by gating mouse delta on `renderViewportState.hovered` so only cursor movement over the 3D viewport dirties the scene.

4. **Executor deleted unrelated code** — AudioEngine init, GameSettings panel, and related wiring were incorrectly removed. All restored.

**Profiling results:** Idle CPU dropped from 61.2% → 1.5%
