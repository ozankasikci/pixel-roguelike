In `EditorScenePreviewRenderer`, add a rendering pass for trigger volumes:

1. After the main scene render and selection overlay passes, add a trigger visualization pass.
2. Query registry for entities with TriggerComponent + TransformComponent.
3. For each trigger:
   - **Box triggers**: Draw a wireframe cube at the trigger's position with the trigger's halfExtents as scale. Use GL_LINES with 12 edges of a unit cube scaled by halfExtents. Color: semi-transparent green (0.2, 0.8, 0.2, 0.4).
   - **Sphere triggers**: Draw a wireframe sphere approximation using 3 circles (XY, XZ, YZ planes) at the trigger's position with the trigger's radius. Use GL_LINE_LOOP with ~32 segments per circle. Color: semi-transparent blue (0.2, 0.4, 0.8, 0.4).
4. Enable alpha blending for the trigger pass. Disable depth writing (glDepthMask(GL_FALSE)) so triggers render as overlays.
5. Use the existing engine shader infrastructure or a simple solid-color shader. The engine already has shaders for wireframe overlays (selection overlay uses them). Check what the selection overlay pass uses and reuse the same approach.

If the selection overlay uses a dedicated wireframe shader, reuse it for trigger volumes with different colors. If it uses the scene shader with special uniforms, create a minimal pass.

Simplest approach: Since ImGuizmo and the selection overlay already draw custom geometry, use the same GL state setup. Create a small helper function `drawTriggerVolumes(registry, viewProjection)` that:
- Binds a simple shader (or uses glUseProgram(0) with fixed-function if available -- but we're Core profile, so need a shader)
- Sets line color uniform
- Draws GL_LINES geometry for each trigger

If creating wireframe geometry is complex, start with a minimal box wireframe (24 vertices for 12 edges) generated once as a VAO, drawn per trigger with model matrix = translate(position) * scale(halfExtents).
