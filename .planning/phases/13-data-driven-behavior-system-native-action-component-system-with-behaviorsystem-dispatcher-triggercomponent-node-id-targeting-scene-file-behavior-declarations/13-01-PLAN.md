**NodeIndex.h** -- per D-16:
```cpp
#pragma once
#include <entt/entt.hpp>
#include <string>
#include <unordered_map>

struct NodeIndex {
    std::unordered_map<std::string, entt::entity> byNodeId;

    void add(const std::string& nodeId, entt::entity entity) {
        if (!nodeId.empty()) {
            byNodeId[nodeId] = entity;
        }
    }

    entt::entity resolve(const std::string& nodeId) const {
        auto it = byNodeId.find(nodeId);
        return it != byNodeId.end() ? it->second : entt::null;
    }

    entt::entity resolve(const std::string& nodeId, entt::entity self) const {
        if (nodeId == "self" || nodeId.empty()) return self;
        return resolve(nodeId);
    }
};
```

**LevelDef.cpp parser changes (per D-06, D-07, D-08):**

The parser currently processes one line at a time. Refactor `loadLevelDef` to a two-pass approach within the same loop:

1. After parsing a top-level entity line (mesh, light, etc.), peek at subsequent lines. If the next line starts with 2+ spaces (leading whitespace), it is a sub-line attached to the current entity.
2. Sub-line types:
   - `interactable "prompt text" distance <float>` (per D-07: moved to sub-line syntax)
   - `behavior <event_type> <action_type> [target <node_id>] [delay <float>] [fire_once] [param_key param_value ...]`
   - `on_activate <action_type> ...` (shorthand for `behavior on_activate <action_type> ...`)
   - `on_enter <action_type> ...` / `on_exit <action_type> ...` / `on_timer <action_type> ...`

Implementation approach: Change the main loop to read a line, check if the NEXT line is indented (use `file.peek()` or buffer the next line). If indented, parse as sub-line and attach to the most recent entity. Use a struct to track "current entity context" (which placement vector, which index).

For the sub-line parser, create a helper function:

namespace {
