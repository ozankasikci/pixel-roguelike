**BehaviorSystem.h:**
```cpp
#pragma once
#include "engine/core/System.h"
#include <string>
#include <vector>

struct PendingAction {
    float fireTime;
    entt::entity source;
    std::string eventType;  // "activate", "enter", "exit", "timer"
    std::size_t actionIndex;
};

class BehaviorSystem : public System {
public:
    void init(Application& app) override;
    void update(Application& app, float deltaTime) override;
    void shutdown() override;

private:
    void processNewActivations(Application& app);
    void processDelayedActions(Application& app, float currentTime);
    void executeActionList(Application& app, entt::entity source,
                           std::vector<struct ActionEntry>& actions,
                           const std::string& eventType, float currentTime);
    void executeAction(Application& app, entt::entity source,
                       struct ActionEntry& action);
    void schedulePendingAction(float currentTime, entt::entity source,
                               const std::string& eventType,
                               std::size_t actionIndex, float delay);

    std::vector<PendingAction> pendingActions_;
};
```

**BehaviorSystem.cpp:**
Inherits System, registered in Gameplay phase.

`init()`: empty (no initialization needed).

`update()`:
1. Get current time from `app.time().elapsed()`
2. Call `processDelayedActions(app, currentTime)` -- pop and execute due actions from pendingActions_
3. Call `processNewActivations(app)` -- check InteractionFocusState for new activations

`processNewActivations()`:
- Get InteractionFocusState from registry.ctx()
- If `focus.activationRequested && !focus.activationConsumed && focus.focused != entt::null`:
  - Get BehaviorComponent on `focus.focused`
  - If found and enabled, call `executeActionList(app, focus.focused, behavior.onActivate, "activate", currentTime)`
  - Set `focus.activationConsumed = true`

`executeActionList()`:
- For each ActionEntry in the list:
  - If `entry.fireOnce && entry.fired`, skip
  - If `entry.delay > 0.0f`, call `schedulePendingAction(...)` instead of immediate execution
  - Otherwise, call `executeAction(app, source, entry)`
  - If `entry.fireOnce`, set `entry.fired = true`

`executeAction()`:
Switch on `action.type`, using NodeIndex from `app.registry().ctx().get<NodeIndex>()` to resolve targets:

- **OpenDoor**: Get DoorComponent on target. If found, set `opening = true`, `progress = 0.0f`. If DoorActionParams has nonzero duration, set `openDuration = params.duration`. Get InteractableComponent on target, set `busy = true`.
- **CloseDoor**: Get DoorComponent on target. Set `opening = false`, `opened = false`, `progress = 0.0f`.
- **ToggleDoor**: Get DoorComponent. If `opened || opening`, treat as CloseDoor. Else treat as OpenDoor.
- **PlaySound**: Log action (actual AudioSourceComponent integration deferred -- the AudioSystem exists but AudioSourceComponent may not be per-entity yet). Publish a `PlaySoundEvent{action.paramString}` on EventBus for future audio integration.
- **SetLight**: Get LightComponent on target. Apply `intensity`, `color`, `radius` from LightActionParams (only modify fields where param values are nonzero).
- **FlickerLight**: Store flicker state. For now, implement as a simple intensity toggle with a timer. Add to a local flicker tracking list or use a FlickerState component. Simplest approach: create a `FlickerState` tag component with duration and rate, and let the BehaviorSystem's update() tick active flickers. Or: just toggle intensity between original and 0.1 for the flicker duration.
- **ShowMessage**: Publish `ShowMessageEvent{text, duration}` on EventBus. GameOverlays already handles message display if it subscribes.
- **Delay**: This action type inserts a delay before subsequent actions in the list. When encountered, schedule remaining actions with accumulated delay. Implementation: in `executeActionList`, track accumulated delay. When a Delay action is hit, add its seconds to the accumulator. Subsequent actions get `entry.delay + accumulated_delay`.
- **EnableEntity**: Get InteractableComponent on target, set `enabled = true`.
- **DisableEntity**: Get InteractableComponent on target, set `enabled = false`.
- **EmitEvent**: Publish a generic `BehaviorEvent{eventName}` on EventBus using the EventActionParams::eventName string.
- **LockPlayer**: Find entity with PlayerInteractionLockComponent, set `active = true`, `remainingTime = params.duration`.
- **UnlockPlayer**: Find entity with PlayerInteractionLockComponent, set `active = false`.
- **TeleportPlayer**: Find entity with PlayerTag + TransformComponent, set `position = params.position`.

`schedulePendingAction()`: Insert into `pendingActions_` sorted by `fireTime = currentTime + delay`. Use `std::lower_bound` for sorted insertion.

`processDelayedActions()`: While front of `pendingActions_` has `fireTime <= currentTime`, pop it, validate entity still exists, look up BehaviorComponent, get the action list by eventType string, execute the action at the stored index.

Define event structs in BehaviorSystem.cpp (or a small BehaviorEvents.h):
```cpp
struct ShowMessageEvent { std::string text; float duration; };
struct PlaySoundEvent { std::string soundId; };
struct BehaviorEvent { std::string name; };
```

**TriggerSystem.h/cpp** -- per D-12, D-13:

```cpp
// TriggerSystem.h
#pragma once
#include "engine/core/System.h"

class TriggerSystem : public System {
public:
    void init(Application& app) override;
    void update(Application& app, float deltaTime) override;
    void shutdown() override;
};
```

`update()`:
1. Find the player entity (PlayerTag + TransformComponent). If no player, return.
2. Get player position from TransformComponent.
3. Iterate all entities with TriggerComponent + TransformComponent:
   - For Box triggers: Check if player position is within trigger AABB (trigger position +/- halfExtents). The AABB test: `abs(playerPos - triggerPos) < halfExtents` on all 3 axes. Per D-13, manual check, no Jolt.
   - For Sphere triggers: Check if `distance(playerPos, triggerPos) < radius`.
   - Track enter/exit transitions using `trigger.playerInside`:
     - If overlap and !playerInside: set playerInside=true, fire onEnter actions on any co-located BehaviorComponent
     - If !overlap and playerInside: set playerInside=false, fire onExit actions
   - For fireOnce triggers: After first enter event, set `trigger.enabled = false`
4. To fire onEnter/onExit: Get BehaviorComponent on the trigger entity. For each ActionEntry in the appropriate list, if entry.delay > 0, schedule via the pending action queue on BehaviorSystem. Otherwise execute immediately. Since TriggerSystem does not own the dispatch logic, the cleanest approach is to set a flag or use a shared queue. 

**Preferred approach**: TriggerSystem publishes a `TriggerActivationEvent{entity, "enter"/"exit"}` on EventBus. BehaviorSystem subscribes to this event and dispatches the appropriate action list. This keeps dispatch centralized in BehaviorSystem.

Alternatively: TriggerSystem directly reads BehaviorComponent and calls into a shared dispatch function. Since BehaviorSystem is the single dispatcher, add a public method `BehaviorSystem::fireActions(Application& app, entt::entity source, const std::string& eventType)` that BehaviorSystem exposes. But this requires TriggerSystem to hold a reference to BehaviorSystem.

**Simplest correct approach**: Use the registry ctx pattern. In BehaviorSystem::update(), after processing activations, also process trigger events. Move the trigger overlap logic INTO BehaviorSystem::update() as a separate step, OR keep TriggerSystem independent and have it set trigger activation flags that BehaviorSystem reads.

**Recommended**: Keep TriggerSystem as a separate System. Have TriggerSystem set a flag on TriggerComponent when state transitions occur (`pendingEnter`, `pendingExit` bools). BehaviorSystem::update() iterates TriggerComponents, reads pending flags, dispatches action lists, and clears the flags.

Add to TriggerComponent (in Plan 01's header, but if immutable, add here):
```cpp
// Runtime state flags for BehaviorSystem to consume
bool pendingEnter = false;
bool pendingExit = false;
```

TriggerSystem::update() sets `pendingEnter = true` on enter transition, `pendingExit = true` on exit transition. BehaviorSystem::update() iterates TriggerComponent+BehaviorComponent, dispatches onEnter/onExit when pending flags are set, then clears the flags.
