<objective>
Delete the MaterialKind enum and refactor the entire rendering pipeline from type-based branching to property-driven feature flags. This is the core surgical change of Phase 7: the shader stops switching on an integer material type and instead reads individual boolean flags and float properties from uniforms.

Purpose: Per D-07, material behavior is fully defined by properties. One PBR uber-shader with no type branching. This also fixes the engine/game layering violation where Renderer.h included MaterialKind.h from the game layer.
Output: Deleted MaterialKind.h, refactored scene.frag/scene.vert, updated RenderMaterialData, updated all call sites across game and editor.
</objective>

9. Replace `materialRoughness()` function (lines 571-594) — roughness is now fully data-driven:
```glsl
float materialRoughness() {
    // Post-refactor: roughness_bias in .material files carries the base roughness.
    // The caller multiplies by uMaterialRoughnessScale and adds uMaterialRoughnessBias.
    // So this function just returns 1.0 — the actual roughness is:
    // clamp(1.0 * uMaterialRoughnessScale + uMaterialRoughnessBias, 0.08, 0.98)
    // which equals: clamp(uMaterialRoughnessScale + uMaterialRoughnessBias, 0.08, 0.98)
    return 1.0;
}
```

WAIT — reconsider. The current roughness computation is: `clamp(materialRoughness() * uMaterialRoughnessScale + uMaterialRoughnessBias, 0.08, 0.98)`. In the old system, `materialRoughness()` returned e.g. 0.74 for wood, and `roughnessScale=1.0, roughnessBias=0.0`, giving 0.74. In the new system, `roughnessBias` in the .material file is set to 0.74, and `roughnessScale=1.0`. So: `1.0 * 1.0 + 0.74 = 1.74` — WRONG.

Correct approach: change the caller line in main() instead. Replace:
```glsl
float roughness = clamp(materialRoughness() * uMaterialRoughnessScale + uMaterialRoughnessBias, 0.08, 0.98);
```
with:
```glsl
float roughness = clamp(uMaterialRoughnessScale + uMaterialRoughnessBias, 0.08, 0.98);
```
